# ADR 0007: 水位梯度自适应并发控制算法

Provider 级并发控制需要自适应调节。标准 AIMD（加法增/乘法减）在小并发场景（limit=2-5）过于激进（+1 等于翻倍）或过于保守（-50% 丢失大量容量）。需要一种算法在小并发范围也能平滑调节。

选定方案：用水位梯度参数替代 AIMD 的固定步长。`capacity` 由 `max` 决定（max 越小越激进），`level` 由 `currentLimit/max` 决定（越接近 max 越保守）。单阶段爬升，429 固定丢 1 格。安全区（limit ≤ max/2）宽松爬升，非安全区必须有利用率证明。

## 核心规则

| 场景 | 行为 |
|------|------|
| 爬升（成功） | effectiveLimit = currentLimit（单阶段，无探针） |
| 429 / 超时 / 队列满 | 丢 1 格（keepRatio = 1 - 1/currentLimit） |
| limit=1 遇 429 | 不再下降（下限保护） |
| 安全区爬升（limit ≤ max/2） | 不需要利用率证明 |
| 非安全区爬升（limit > max/2） | 必须有 limitReached（有请求排过队） |

## Considered Options

1. **标准 AIMD（TCP 拥塞控制风格）**：小并发场景步长不合理，limit=2 时 +1 等于翻倍。
2. **固定上限（无自适应）**：无法利用 Provider 空闲容量，浪费并发度。
3. **令牌桶 + 动态速率**：实现复杂，SSE 长连接场景不适用。
4. **选定方案**：水位梯度参数 + 利用率门控。

## Consequences

- 算法参数少（只有 max），capacity/level 由 max 派生，不需要额外配置。
- limit=1 是下限，不会因连续 429 导致 Provider 完全不可用。
- 安全区爬升宽松、非安全区保守，平衡了收敛速度和稳定性。
- 信号量超时/队列满按 429 同等处理（丢 1 格 + 冷却），保持行为一致性。
