# Monitor.vue 页面审查报告

对比 feat 分支 vs main 分支，审查功能性 bug 和遗漏。

## 功能性 Bug

### BUG-1: `request_start` 事件不会触发 UI 更新 (P1)

**文件**: `frontend/src/composables/useMonitorData.ts` 第 82-86 行

`activeRequests` 使用 `shallowRef`，但 `request_start` handler 通过 `unshift()` 原地修改数组，**未调用 `triggerRef()`**。`shallowRef` 只在 `.value` 被整体替换时触发响应式更新，原地修改不会触发。

对比 `stream_content_update` handler 正确调用了 `triggerRef(activeRequests)`。

**影响**: SSE 推送 `request_start` 事件时，新请求不会出现在表格中，直到下一次 `request_update`（全量替换）到来才会刷新。

**注意**: 此 bug 在 main 分支中同样存在（非回归）。

**修复**: 在 `unshift` 后加 `triggerRef(activeRequests)`。

```typescript
case "request_start": {
  const req = data as ActiveRequest;
  if (!recentCompleted.value.some((r) => r.id === req.id)) {
    activeRequests.value.unshift(req);
    triggerRef(activeRequests);  // 缺少这一行
  }
  break;
}
```

### BUG-2: i18n key 缺失 — `providerStatsHide` / `providerStatsShow` (P2)

**文件**: `frontend/src/i18n/locales/en/monitor.json`

`monitor.providerStatsHide` 和 `monitor.providerStatsShow` 仅存在于 `zh-CN/monitor.json`，**不存在于 `en/monitor.json`**。feat 分支 Monitor.vue 新增了 Collapsible 折叠/展开按钮，使用了这两个 key。

**影响**: 英文环境下，折叠按钮显示为原始 key 而非翻译文本。

**修复**: 在 `en/monitor.json` 中添加：
```json
"providerStatsHide": "Hide",
"providerStatsShow": "Show"
```

## 数据遗漏

### OMIT-1: 每个 Provider 的队列信息不再显示 (P2)

**main 分支**: `ConcurrencyPanel.vue` 展示每个 Provider 的 `queued` 数量和 `queueLimit`（排队数 / 队列容量上限）。

**feat 分支**: `ConcurrencyPanel.vue` 文件存在但**未被任何组件引用**（死代码）。并发展示移到了 `MonitorHeader.vue`，但只显示 active/limit 进度条，**丢弃了 `queued` 和 `maxQueueSize` 字段**。

后端 `ProviderConcurrencySnapshot` 类型包含 `queued`、`queueTimeoutMs`、`maxQueueSize` 三个字段，feat 的 MonitorHeader 只用了 `active` 和 `maxConcurrency`/`adaptiveLimit`。

**影响**: 用户无法从 Monitor 页面看到各 Provider 的排队情况（排队数、队列容量），只能看到全局的 `queuedCount` 数值。

**建议**: 在 MonitorHeader 的并发条中补充队列信息，或保留 ConcurrencyPanel 的展示。

### OMIT-2: RuntimePanel 不再展示 `activeRequests` 和 `uptime` (P3, 设计意图)

**main 分支**: `RuntimePanel.vue` 展示 uptime、memory RSS、heap usage、active handles、active requests、event loop delay 共 6 项。

**feat 分支**: `RuntimePanel.vue` 仅展示 memory RSS、event loop delay、active handles、heap usage 共 4 项。`uptime` 移到了 Secondary Strip 面板，`activeRequests`（来自 RuntimeMetrics）不再展示。

**影响**: `RuntimeMetrics.activeRequests` 字段（后端采集的 Node.js 活跃 HTTP 请求数）不再显示。这与应用层的"活跃请求计数"（activeRequests.length）含义不同，后者是代理请求计数，前者是底层 HTTP 句柄数。

**建议**: 如果是刻意简化则可忽略。否则应在 RuntimePanel 补回。

## 无 Bug 项（已验证）

| 检查项 | 结论 |
|--------|------|
| SSE 7 种事件类型与后端匹配 | 匹配：request_start/update/complete, concurrency_update, stats_update, runtime_update, stream_content_update |
| SSE 断线重连 + 活跃请求同步 | 正确：reconnect 后调用 `syncActiveOnSSEReconnect` 做增量 diff |
| SSE 可见性断开（30s 隐藏） | 正确：独立于 tick timer 的 visibility 处理 |
| 初始数据加载（Promise.allSettled） | 正确：5 个 API 并行加载，各自独立处理 fulfilled/rejected |
| Kill 请求流程 | 正确：DELETE → 本地移除 → toast。`killTarget` 在 `activeRequests` 中查找（含 queued 请求） |
| `isKillable` 条件 | 正确：`status === "pending"` 涵盖 active 和 queued 请求，completed/failed 不显示 kill 按钮 |
| 已完成请求的 streamContent 加载 | 正确：优先用 existing.streamContent，否则从 API 拉取 |
| Log detail 加载（版本号防竞态） | 正确：`loadVersion` 递增机制 |
| 页面隐藏时 tick timer 暂停 | 正确：`handleMonitorVisibility` 停止/恢复 3s tick |
| Tab 切换数据源 | 正确：active→streamingRequests, queued→queuedRequests, recent→recentCompleted |
| expandedRowId 展开/收起 | 正确 |
| shallowRef 在 request_update/request_complete/executeKill 中的使用 | 正确：都是通过 `.filter()` 创建新数组赋值，触发 shallowRef |
| 类型变更（AttemptSnapshot 增加 model?/apiType?） | 向后兼容，非 breaking |
